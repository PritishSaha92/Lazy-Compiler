# Held-out evaluation protocol, 23 October 2026

The new split has 18 synthetic workloads: three pointwise, four reductions,
four matrix products, four fused compositions, and three rectangular attention
cases. These are original public-semantic test inputs, not the competition's
unavailable hidden data. Source definitions are in
[`expressions_holdout.py`](../tests/expressions_holdout.py).

The corpus and its provenance live under
[`artifacts/validation/holdout-2026-10-23`](../artifacts/validation/holdout-2026-10-23/README.md).
The manifest is frozen before PTX compiler evaluation or performance-policy
selection using this split. It records IR, launch metadata, reference arrays,
test-source hashes, and the initial baseline source hash. Generation-only
repairs of an upstream-invalid multi-axis mean and setup intermediates are
disclosed; no backend result motivated them. The freeze check verifies intended
input names, ordering, and shapes against the actual traced graph.

Normal inputs at new seed offsets 37 and 89 and inputs scaled by eight at 137
give 54 planned correctness cases. An independent CPU PyTorch/NumPy sanity pass
checks those references without compiling or running PTX. Per-workload
tolerances remain fixed.

Before testing, freeze the candidate source and explicit optimization options.
Verify the split using `python tests/freeze_holdout.py --verify`. Evaluate both
baseline and candidate under the same correctness conditions, retain failures,
and then measure eligible candidates with serialized, interleaved timing rounds.
Any policy revision informed by these outcomes turns this split into development
data; future claims must acknowledge that or use a fresh evaluation split.

The existing checker supports these references:

```powershell
$holdout=(Get-ChildItem -LiteralPath 'artifacts/validation/holdout-2026-10-23' -Directory).FullName
python tools/check_compiler.py --mode remote --references tests/expressions_holdout.py --seeds 37,89 --patterns normal --warmup 1 --iters 3 --report artifacts/validation/holdout-normal-results.json @holdout
python tools/check_compiler.py --mode remote --references tests/expressions_holdout.py --seeds 137 --patterns wide --warmup 1 --iters 3 --report artifacts/validation/holdout-wide-results.json @holdout
```

Those are reproduction commands, not recorded test results. Keep evaluation
reports outside the frozen corpus and record which compiler/policy produced
each one. The compiler, GPU memory-safety tools, and official runner have not
been exercised by corpus generation itself.

## Recorded release evaluation

The default release candidate passed all **54 of 54 held-out numerical cases**
on the official RTX 5090. Both normal seeds passed all 18 workloads, and the
scaled-input condition also passed all 18. The earlier public, fresh, and native
layout gates passed another 103 cases, giving **157 of 157 primary cases**
across 51 distinct workload packages.

The candidate was copied before evaluation to
[`release-candidate`](../artifacts/validation/phase2/release-candidate/candidate-source.json).
Its backend SHA-256 is
`0373bbc64340ae37274a67a92deb7320915ff4aa5cef97a231b3ac1ec7a2cc59`;
the unchanged CLI SHA-256 is
`4ed3fb67833b7de20693c7cb3f163a4646cac8d3a71e63649c1af1bccd37ce56`.
The corpus seal was verified before and after evaluation. No candidate policy,
workload, tolerance, or reference was changed after seeing these results.

An executable copy of the earlier `3e68...` backend was not found in the
inspected workspace, repository history, or preserved archive. The search scope
is recorded in
[`historical-baseline-source-audit.json`](../artifacts/validation/phase2/historical-baseline-source-audit.json).
Instead, an explicitly labeled strict-arithmetic ablation used the **same
frozen candidate backend**, disabling compensated/widened dots and accumulation
contraction while preserving its other defaults. It also passed **54 of 54**
held-out cases. This is not a comparison with the missing historical revision,
and these outcomes do not establish an additional compensation pass-rate gain
on the new split. The earlier public scaled-matmul counterexample remains
documented separately.

Across the 54 held-out cases, the default had a smaller maximum absolute
reference error in 15 cases, the same value in 36, and a larger value in three;
all remained within their original tolerances. Those diagnostics and all cases
are preserved in
[`release-holdout-policy-comparison.json`](../artifacts/validation/phase2/release-holdout-policy-comparison.json).
The three-iteration timings collected during correctness checks are incidental;
they are not an interleaved performance comparison.

The consolidated evidence, including exact report hashes, is
[`release-validation-summary.json`](../artifacts/validation/phase2/release-validation-summary.json).
Default and strict reports remain separate under `release-holdout-default/` and
`release-holdout-strict/`. No manual reruns or reported infrastructure failures
were needed; internal bounded HTTP retry counts are not recorded by the checker.

The reusable evaluator first snapshots the selected source, then checks the
manifest-defined package list and runs the two input batches serially:

```console
python tests/evaluate_holdout.py prepare --snapshot artifacts/validation/new-candidate --expected-backend-sha EXPECTED_SHA256
python tests/evaluate_holdout.py run --snapshot artifacts/validation/new-candidate --report-dir artifacts/validation/new-heldout-results --policies default strict
```

Those future runs would reuse an already observed split. Any optimization
chosen using these recorded outcomes must treat this corpus as development data
and use another untouched split for a fresh generalization claim.
